# 네트워크 · FastDDS 트러블슈팅

## 발생 증상

- TurtleBot이 기존 Wi-Fi 또는 의도하지 않은 SSID로 재연결됨.
- FastDDS에 `Matching unexisting participant`가 반복 출력됨.
- bringup은 `Run!`인데 WSL에서 `/odom`, `/scan`, `/cmd_vel`이 간헐적으로 보이지 않음.
- Windows 모바일 핫스팟 환경에서 WSL과 TurtleBot 간 UDP 경로가 불안정함.

## 원인

1. `/etc/netplan`의 여러 YAML 파일이 동시에 Wi-Fi 설정을 제공함.
2. cloud-init가 생성한 `50-cloud-init.yaml`에 기존 SSID가 남아 자동 연결됨.
3. FastDDS Discovery Server가 Wi-Fi/IP 변경 또는 비정상 종료 뒤 사라진 participant 정보를 유지함.
4. 하나의 WSL 터미널에서 Domain 5(jshim)와 Domain 6(tb1) 환경을 섞으면 ROS 2 노드가 다른 Discovery Server에 연결됨.

## Wi-Fi 고정 원칙

- 현재 사용할 SSID만 `/etc/netplan/99-wifi.yaml`에 둔다.
- 현재 실험 SSID: `<SSID>`.
- `AI_academy_302`는 활성 Netplan YAML에서 제거한다.
- 이 TurtleBot 환경은 `NetworkManager.service`가 없으므로 `renderer: networkd`를 사용한다.
- cloud-init 설정 파일은 `.disabled` 확장자로 바꿔 Netplan 적용 대상에서 제외한다.

```yaml
network:
  version: 2
  renderer: networkd
  wifis:
    wlan0:
      dhcp4: true
      optional: true
      regulatory-domain: KR
      access-points:
        "<SSID>":
          password: "<WIFI_PASSWORD>"
```

적용 및 확인:

```bash
sudo chown root:root /etc/netplan/99-wifi.yaml
sudo chmod 600 /etc/netplan/99-wifi.yaml
sudo netplan generate
sudo netplan apply
iw dev wlan0 link
hostname -I
```

정상 기준: `iw dev wlan0 link`에 `SSID: <SSID>`가 출력된다.

## FastDDS 클린 재시작

다음 상황에서는 실행 전 클린 재시작을 한다.

- 핫스팟/공유기 변경
- IP 주소 변경
- `Matching unexisting participant` 반복
- ROS 노드가 간헐적으로 발견되지 않음

1. 해당 로봇의 WSL 노드, bringup, FastDDS 창을 Ctrl+C로 종료한다.
2. 해당 로봇 SSH에서 Discovery Server를 종료한다.

```bash
pkill -f 'fastdds.py discovery|fast-discovery-server' || true
sleep 1
```

3. 포트가 비었는지 확인한다.

```bash
# jshim
ss -lunp | grep ':11811' || true

# tb1
ss -lunp | grep ':11812' || true
```

출력이 없으면 정상이다.

4. 재시작 순서:

```text
jshim FastDDS → jshim bringup → tb1 FastDDS → tb1 bringup →
WSL tb1 teleop → WSL jshim 통합 SLAM → WSL RViz
```

## 도메인 분리 규칙

| 용도 | ROS_DOMAIN_ID | Discovery Server |
|---|---:|---|
| jshim SLAM | 5 | jshim IP:11811 |
| tb1 teleop | 6 | tb1 IP:11812 |

- tb1 teleop, jshim 통합 launch, RViz는 각각 별도 WSL 터미널에서 실행한다.
- 실행 중인 teleop 터미널에 jshim 환경변수를 붙여넣지 않는다.
- 실행 중 `pkill`하면 해당 로봇의 ROS 2 연결이 즉시 끊긴다.

## 확인 우선순위

1. TurtleBot 내부 `turtlebot3_ros` 프로세스 존재 여부.
2. TurtleBot 내부 `/odom` 발행 여부.
3. WSL에서 teleop 또는 SLAM 실행.
4. RViz로 map/scan 확인.
